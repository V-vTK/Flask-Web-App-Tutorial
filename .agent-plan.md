## Current behaviour (Flask + Flask-SQLAlchemy + Flask-Login, SQLite, Jinja templates)
- `main.py`: `create_app()`; `app.run(debug=True)` (ignores $PORT, default 5000).
- DB: SQLite `database.db` (instance/ dir with Flask-SQLAlchemy 3), tables User(email unique, password, first_name, notes) and Note(data, date, user_id). Created at startup.
- `GET/POST /login`: unknown email -> flash "Email does not exist."; wrong password -> "Incorrect password, try again."; success -> flash "Logged in successfully!", redirect `/`.
- `GET /logout` (login required) -> redirect `/login`.
- `GET/POST /sign-up`: validation order: email exists ("Email already exists."), email <4 chars, first name <2, passwords differ ("Passwords don't match."), password <7; success -> user created, logged in, "Account created!", redirect `/`.
- `GET/POST /` (login required, else redirect to `/login?next=/`): POST `note` empty -> "Note is too short!", else saved "Note added!"; page lists the user's notes.
- `POST /delete-note` JSON `{noteId}`: deletes the note if owned by current user; returns `{}`. (No login_required: anonymous request raises 500 because current_user.id is missing — existing behaviour, leave alone.)
- Static: `static/index.js` (deleteNote fetch + reload).

## The bug
`website/auth.py` uses `generate_password_hash(password1, method='sha256')`. Werkzeug >= 3.0 removed 'sha256' -> `ValueError: Invalid hash method 'sha256'` -> sign-up 500 on deployment. requirements.txt is also unpinned.

## Target / migration steps
1. (Tests step) Write failing test: POST /sign-up with valid data -> expect redirect to `/` and user stored with a hash that `check_password_hash` accepts.
2. Minimal fix: use `generate_password_hash(password1)` (default scrypt/pbkdf2; `method='pbkdf2:sha256'` is also acceptable). Existing sha256 hashes in old DBs still verify through check_password_hash.
3. Deployment: start the app on $PORT (5001 requested) in foreground without debug reloader, e.g. `flask --app main run --host 0.0.0.0 --port $PORT`. Do not change main.py unless needed.
4. .gitignore fixed (a line had been glued: `website/database.db# agent-lab...`); `*.db` added.
