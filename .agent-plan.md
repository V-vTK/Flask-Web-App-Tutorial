# Plan: rewrite Flask notes app in React + TypeScript (no Python)

## Current behaviour (Flask + Flask-SQLAlchemy + Flask-Login, SQLite, Jinja + Bootstrap 4 CDN)
- `main.py`: `create_app()`; dev server on 5000. Container runs gunicorn on `$PORT` (5001).
- DB: SQLite; User(id, email unique, password hash, first_name), Note(id, data<=10000, date, user_id). Created at startup.
- Auth: Flask-Login session cookie + `remember_token` cookie (remember=True). Unauthenticated access to `/` redirects to `/login?next=%2F`.
- Routes:
  - `GET/POST /login` (form: email, password). Unknown email -> flash error "Email does not exist."; wrong password -> "Incorrect password, try again."; success -> flash "Logged in successfully!", 302 `/`. Page re-renders (200) on failure.
  - `GET /logout` (login required) -> 302 `/login`.
  - `GET/POST /sign-up` (email, firstName, password1, password2). Check order: email exists "Email already exists."; email <4 "Email must be greater than 3 characters."; firstName <2 "First name must be greater than 1 character."; mismatch "Passwords don't match."; password <7 "Password must be at least 7 characters."; success -> create user, log in, flash "Account created!", 302 `/`.
  - `GET/POST /` (login required): POST `note` empty -> error "Note is too short!"; else stored, "Note added!". Lists the user's notes (HTML-escaped) with a × delete button, textarea#note, "Add Note" button.
  - `POST /delete-note` JSON `{noteId}` -> `{}`; deletes only if owned by the current user (anonymous request = 500 in the original).
  - `/static/index.js` (deleteNote: POST then `location.href="/"`). Unknown route 404, wrong method 405.
- UI: Bootstrap 4.4.1 + Font Awesome via CDN, dark navbar (Home/Logout when authenticated; Login/Sign Up otherwise, ids `home`, `logout`, `login`, `signUp`), flash alerts (`alert-danger` for error, `alert-success` otherwise, dismissible, shown once), titles Home/Login/Sign Up, headings "Notes", "Login", "Sign Up", same labels/placeholders/ids/names.

## Target design (TypeScript only)
- Backend: Node + Express + TypeScript, SQLite (better-sqlite3), bcrypt/scrypt hashing, cookie sessions (session + `remember_token` cookies), flash messages stored in the session. Keeps the same endpoints, form-encoded POSTs, redirects, status codes and JSON delete API.
- Frontend: React + TypeScript (Vite) SPA using react-router with the same paths (`/`, `/login`, `/sign-up`, `/logout`), same Bootstrap markup/classes/ids and CDN assets; flash messages shown once after the redirect. The Express server serves the built SPA (and `/static/index.js` if needed) so one process serves everything on `$PORT`.
- Deploy: replace Dockerfile (multi-stage node build, non-root, SQLite volume), compose.yaml (port 5001, healthcheck on `/login`), README, .env.example, .gitignore; remove Python files (main.py, website/, requirements.txt).

## Migration steps
1. (Tests step) Black-box tests (`.agent-tests`: rest, html, playwright) run against the ORIGINAL app via `BASE_URL`; they must stay passable against the rewrite unchanged.
2. Scaffold Node/TS project (server + client), DB schema, auth/session/flash middleware.
3. Port routes and validation exactly (order and messages above); build React pages reproducing the templates.
4. Switch `run.start` to the new app, update Dockerfile/compose, delete Python code.
5. Re-run all layers against the new app; deploy both (backend and frontend served together).

## Must stay identical
Every route, status code and redirect, flash text and category styling, validation order and length boundaries, login-required behaviour, per-user note privacy, note HTML escaping, note ordering, cookies on login, 404/405 behaviour, visible UI (markup, classes, ids, labels, placeholders, titles, navbar state), port 5001 and `/login` health path.
